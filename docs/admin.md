# Регистрация КД: инструкция администратора

Один путь по шагам: сборка на ПК, подготовка сервера, первый запуск, журнал целиком
(резерв, замена, восстановление), обновление, откат и резервные копии. Решения, на которых все
построено, — в [decisions.md](decisions.md).

Команды на ПК выполняются в терминале Ubuntu внутри WSL, на сервере — в терминале по SSH.
Команды одни и те же. Установка ПК и бот на ПК пошагово — в [pc.md](pc.md), сервер и переезд
бота с ПК на сервер пошагово — в [server.md](server.md).

## 1. Что нужно

- **ПК (Windows):** WSL с Ubuntu 24.04, Docker Desktop с интеграцией WSL, в Ubuntu `git` и
  `uv`, клон репозитория в `~/doc-registry-bot`. Проверка и установка по шагам — [pc.md](pc.md),
  шаги 0–4: что уже стоит, не ставится заново.
- **Сервер:** виртуальная машина Ubuntu с доступом по SSH и интернетом для установки Docker и
  обновлений Ubuntu. Служба мессенджера работает на этом же сервере в своем Docker.
- **Сведения:** ваш числовой `userId` в мессенджере, коды организации, сетевая папка для копий
  и учетная запись с правом записи в нее.

## 2. Сборка на ПК

```bash
cd ~/doc-registry-bot
git pull
scripts/build.sh
```

Скрипт прогоняет проверки и тесты, собирает образы и пишет в `dist/`:

- `doc-registry-bot-<версия>.tar.gz` — образы бота, копии и PostgreSQL одним файлом;
- `compose.yaml`, `update.sh`, `backup.sh`, `import.sh`, `users.sh`, `.env.example`.

Тесты базы нуждаются в PostgreSQL: перед первой сборкой
`docker compose -f tests/compose.yaml up -d`.

## 3. Подготовка сервера (один раз)

Подробно, с проверками на каждом шаге, — [server.md](server.md), шаги 1–8. Коротко:

Docker Engine:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker "$USER"
sudo timedatectl set-timezone Europe/Moscow
```

После `usermod` выйдите из SSH и зайдите снова.

Общая сеть со службой мессенджера:

```bash
docker network create messenger
```

В `compose` службы мессенджера подключите ее к этой сети и уберите публикацию порта 8888 наружу:
у службы нет авторизации, и кто до нее достучится, пишет от имени бота.

```yaml
services:
  <имя службы>:
    # строку ports с 8888 удалить
    networks:
      - default
      - messenger

networks:
  messenger:
    external: true
```

Затем перезапустите службу мессенджера (`docker compose up -d` в ее папке) и запишите имя ее
контейнера: `docker ps --format '{{.Names}}'`.

Папка бота и файлы с ПК:

```bash
sudo mkdir -p /opt/doc-registry-bot
sudo chown "$USER" /opt/doc-registry-bot
```

На ПК:

```bash
scp dist/doc-registry-bot-1.1.0.tar.gz dist/compose.yaml dist/*.sh dist/.env.example пользователь@сервер:/opt/doc-registry-bot/
```

На сервере:

```bash
cd /opt/doc-registry-bot
cp .env.example .env
chmod 600 .env
chmod +x *.sh
nano .env
```

В `.env` заполните `MESSENGER_URL` (имя контейнера службы и порт 8888), `OWNER_IDS`,
`ORG_CODES`, базу (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`) и сетевую папку
`BACKUP_SHARE*`. `BOT_VERSION` должна совпадать с версией файла образов (`1.1.0`). Откуда брать
каждое значение и как создается база — [server.md](server.md), шаг 7. Строки базы
заполняются до первого запуска: потом PostgreSQL их не перечитывает.

## 4. Первый запуск

С одной учетной записи бота отвечает только один бот: если от ее имени отвечает еще кто-то, на
одно сообщение будет две регистрации.

1. **Учетная запись:** убедитесь, что от имени учетной записи бота сейчас никто не отвечает.
2. **Журнал:** нужен файл CSV (или книга Excel), в первой строке восемь столбцов журнала:
   Наименование, Обозначение, ФИО регистрирующего, Дата регистрации, Проект, Отметка учета,
   Примечание (первичное применение), Примечание (краткая характеристика). Лишние столбцы не
   мешают. Перенесите файл на сервер:
   `scp журнал.csv пользователь@сервер:/opt/doc-registry-bot/`.
3. **Сервер:** загрузите образы, сделайте резерв и загрузите журнал (бот еще не запущен):

   ```bash
   cd /opt/doc-registry-bot
   docker load -i doc-registry-bot-1.1.0.tar.gz
   ./backup.sh
   ./import.sh журнал.csv
   ```

   `import.sh` сначала проверит файл и напишет «Файл годится, записей: N.», потом спросит
   «Продолжить? (да/нет)». Ответ «Журнал заменен. Было записей: 0, стало: N.» означает, что все
   строки в базе. Если в файле есть ошибки (повтор обозначения, неразобранная дата, нет
   столбца), не загружается ничего: исправьте файл и повторите обе команды.
4. **Сервер:** запустите бота:

   ```bash
   ./update.sh doc-registry-bot-1.1.0.tar.gz
   ```

   Строка «Бот работает, версия 1.1.0.» означает, что бот запущен. Вам в мессенджер придет «Бот
   регистрации КД запущен, версия 1.1.0.».
5. **Проверка:** отправьте боту «Выгрузить журнал» и сверьте число записей и последние номера
   нескольких серий с исходным файлом журнала.
6. **Доступ:** загрузите список сотрудников файлом `./users.sh пользователи.csv` (раздел 5) или
   выдайте доступ командой «Выдать доступ: ФИО, ФИО, ...» (полное ФИО или ID) с ответом «Без
   инструкции». Новым сотрудникам в будущем отвечайте «Да»: им уйдет инструкция, а бот сообщит,
   кому она не дошла.

**Если что-то пошло не так:** `docker compose stop bot`. Журнал вместе с номерами, выданными
ботом, сохраняет `./backup.sh` (файл `backups/журнал-....csv`).

## 5. Журнал целиком и список пользователей

Команды выполняются на сервере в папке бота (`cd /opt/doc-registry-bot`). Бот может работать:
регистрации на время замены ждут, пока она закончится.

**Резерв (он же выгрузка журнала):**

```bash
./backup.sh
```

В папку `backups/` попадают `журнал-<дата_время>.csv` (весь журнал, файл делается и для пустого
журнала) и `база-<дата_время>.dump` (полная копия базы: журнал, доступы, журнал действий).
Файлы доступны только вам.

**Замена всего журнала файлом:**

```bash
./backup.sh
./import.sh журнал.csv
```

`import.sh` работает, только если резерв сделан не раньше чем 30 минут назад и журнал с тех
пор не менялся. Иначе ответ «Сначала сделайте резерв: ./backup.sh» или «Журнал изменился после
резерва», и база не трогается. Повторная замена тоже требует нового резерва. Доступы
пользователей и журнал действий при замене не меняются.

**Вернуть журнал из резерва** (например, после неудачной замены):

```bash
./backup.sh
./import.sh backups/журнал-2026-11-11_101500.csv
```

После замены `import.sh` сам пишет, каким файлом вернуть прежний журнал.

**Доступ списком:**

```bash
./users.sh пользователи.csv
```

В файле два столбца, `ID` и `ФИО`, в первой строке заголовок, разделитель `;` или `,`:

```text
ID;ФИО
5001;Сидоров Сидор Сидорович
5002;Петров Петр Петрович
```

Заготовка файла: `./contacts.sh > контакты.csv` выводит всех контактов учетной записи бота в этом
виде; лишние строки удалите.

Доступ выдается без инструкции, права администраторов не меняются. Ошибка в любой строке (не
число в ID, пустое ФИО, повтор ID): не загружается ничего.

Файлы CSV из табличного редактора подходят как есть (UTF-8 или Windows-1251).

## 6. Обновление

На ПК: `git pull`, `scripts/build.sh`, затем

```bash
scp dist/doc-registry-bot-1.2.0.tar.gz пользователь@сервер:/opt/doc-registry-bot/
```

На сервере:

```bash
cd /opt/doc-registry-bot
./update.sh doc-registry-bot-1.2.0.tar.gz
```

Скрипт делает копию базы, загружает образы, перезапускает бота и проверяет, что поднялась нужная
версия. Если изменились `compose.yaml` или скрипты `*.sh`, скопируйте их с ПК тоже.

**Откат на предыдущую версию:** `./update.sh --rollback`. Данные не теряются: схема базы меняется
только добавлением, и прежняя версия на ней работает.

## 7. Резервные копии

- Каждую ночь в `BACKUP_TIME` (по умолчанию 03:00) делается копия базы. Хранится
  `BACKUP_KEEP_DAYS` дней (по умолчанию 30) на сервере и в сетевой папке.
- Если копия не сделана или не попала в сетевую папку, бот пишет владельцу.
- Копия вручную: `docker compose exec backup /usr/local/bin/backup.sh now` (или `./backup.sh`:
  журнал и копия базы в папку `backups/` рядом с ботом).
- Список копий на сервере: `docker compose exec backup ls -l /backups`.
- **Восстановление** (только при беде, записи после копии пропадут):

  ```bash
  docker compose cp doc-registry-2026-11-10_030000.dump backup:/backups/   # если копия из сетевой папки
  ./update.sh --restore doc-registry-2026-11-10_030000.dump
  ```

  Копия из `./backup.sh` восстанавливается так же: сначала
  `docker compose cp backups/база-2026-11-11_101500.dump backup:/backups/`, затем
  `./update.sh --restore база-2026-11-11_101500.dump`.

## 8. Присмотр

- Журнал программы: `docker compose logs -f bot`.
- Состояние контейнеров: `docker compose ps`.
- Владельцу приходят: «бот запущен» при старте, «связь восстановлена» после перерыва дольше
  5 минут, сообщения о сбое копии.
- Изменили `.env` — примените командой `docker compose up -d` (простой `restart` новый `.env` не
  перечитает).

## 9. Проверка на ПК

Пошагово — в [pc.md](pc.md): тот же порядок, что на сервере, в терминале Ubuntu внутри WSL и в
Docker Desktop. Служба мессенджера в своем контейнере, общая сеть `messenger`, `.env` с рабочей
учетной записью бота. **Пока бот на ПК работает, никто другой от имени этой учетной записи не
отвечает**, после проверки остановите бота (`docker compose stop bot`).

## 10. Команды в боте

Управление — сообщениями боту в мессенджере. Полный список с примерами бот присылает сам:
напишите ему «Инструкция администратора». Коротко:

| Команда | Что делает |
|---|---|
| `Выдать доступ: ФИО или ID, ...` | выдать доступ; ответ «Да», «Без инструкции» или «Нет» |
| `Удалить доступ: ФИО или ID` | снять доступ после «Да» |
| `Отправить инструкцию: ФИО или ID` | повторно отправить инструкцию тому, у кого есть доступ |
| `Пользователи` | у кого есть доступ |
| `Выгрузить журнал` | журнал КД файлом CSV |
| `Журнал действий` | кто что делал, файлом CSV за год |
| `Отправить сообщение: ФИО или ID, ...` и со следующей строки `Сообщение: текст` | сообщение с файлами после «Да»; «всем» — всем с доступом |
| `Назначить администратора: ФИО или ID` | только владелец |
| `Снять администратора: ФИО или ID` | только владелец |
| `Администраторы` | только владелец |

Людей указывайте полным ФИО или ID: часть ФИО бот не примет. Если полное ФИО совпало у двух
человек, бот покажет их ID и попросит повторить команду с ID.
