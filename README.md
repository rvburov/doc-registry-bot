# Регистрация КД

Бот в корпоративной программе-мессенджере выдает конструкторским документам обозначения по
ГОСТ 2.201-80 и ведет журнал регистрации. Своя база PostgreSQL, запуск в Docker, управление
командами в боте.

- [Решения и план](docs/decisions.md) — что и почему сделано так.
- [Инструкция администратора](docs/admin.md) — сборка, установка на сервер, первый запуск,
  обновление, откат, резервные копии.
- [Бот на ПК](docs/pc.md) — проект на диске Windows в VS Code, Docker в WSL, связь со службой
  мессенджера, сборка, запуск, выгрузка файлов и резервные копии пошагово.
- [Бот на сервере](docs/server.md) — Ubuntu на виртуальной машине, перенос базы с ПК, запуск,
  выгрузка файлов и резервные копии пошагово.
- [Правила для ИИ-агентов](AGENTS.md).

## Как работает

```
программа-мессенджер ── служба API мессенджера (свой Docker, порт 8888 только внутри)
                              │  поток событий STOMP /notify, HTTP API
                              ▼
               ┌──────── наш Docker (deploy/compose.yaml) ────────┐
               │  bot ── очередь ── обработка по одному ── ответы │
               │   │                                              │
               │  postgres (журнал, люди, ожидания, журнал        │
               │            действий)                             │
               │  backup ── копии по заявке бота ── папки, сеть   │
               └──────────────────────────────────────────────────┘
```

- Сотрудник пишет боту «Действие: Регистрация / Номер: АБВГ.301121.ХХХ / ...», бот выдает первый
  свободный номер серии и отвечает. Первый документ новой серии, удаление и изменение — после
  ответа «Да».
- Администратор и главный администратор могут регистрировать за другого сотрудника, указав
  полное ФИО в заявке или строке книги. У обычного пользователя подставляется его ФИО из
  карточки мессенджера. Исполнитель в журнале действий всегда фактический отправитель.
- Наименование, проект, отметку учета и оба примечания может исправлять любой пользователь с
  доступом, ФИО регистрирующего, подразделение и актуальность — только администратор или
  главный администратор. Подразделение нового документа берется из карточки API,
  актуальность автоматически ставится «Зарегистрирован». Аннулирование сохраняет занятый номер. Необязательные
  поля доступны и при регистрации сообщением или списком. Пустое значение при правке очищает
  необязательное поле, пропущенное сохраняется. Правка выполняется после подтверждения, в
  истории сохраняются исполнитель и прежние и новые значения.
- Администраторы выдают и снимают доступ, делают выгрузку журнала в CSV, отправляют сообщения с
  файлами. Главный администратор (владелец, OWNER_IDS в `.env`) назначает администраторов, делает
  резервную копию и заменяет весь журнал файлом CSV через чат. Раз в неделю бот напоминает ему
  сделать копию; ночной копии по расписанию нет.
- Сообщения, пришедшие, пока бот не работал, он дочитывает при подключении (до 24 часов).
- На сервере: `./backup.sh` (резерв журнала и базы), `./import.sh ФАЙЛ` (замена всего журнала,
  только после свежего резерва), `./users.sh ФАЙЛ` (доступ списком), `./contacts.sh` (ID и ФИО
  контактов бота).

## Разработка

```bash
uv sync                                      # окружение
docker compose -f tests/compose.yaml up -d   # PostgreSQL для тестов на порту 5457
uv run ruff format --check . && uv run ruff check . && uv run mypy && uv run pytest
```

Файл для установки собирает GitHub после зеленых проверок (Actions → Artifacts), на ПК он
скачивается в браузере. Два способа пошагово — [получить файл](docs/pc.md#5-файл-бота) и
[обновить бота на ПК](docs/pc.md#17-обновление-на-пк): сборка на своем ПК или готовый архив из
GitHub Actions.

## Устройство

| Где | Что |
|---|---|
| `src/doc_registry_bot/registry/` | логика без базы и сети: обозначения, ЕСКД, разбор сообщений, ответы, книга Excel, инструкция |
| `src/doc_registry_bot/bot/` | поведение: регистрация, просмотр и правка, команды, роли, ожидания ответа |
| `src/doc_registry_bot/db/`, `migrations/` | таблицы и миграции Alembic |
| `src/doc_registry_bot/messenger/` | единственная дверь в сеть: HTTP API и поток STOMP службы мессенджера |
| `src/doc_registry_bot/service.py` | очередь, дочитывание, уведомления владельцу, чистка |
| `src/doc_registry_bot/importer.py` | выгрузка журнала, замена журнала из файла после резерва, доступ из файла |
| `src/doc_registry_bot/backups.py`, `bot/copies.py` | резервная копия одним снимком базы, напоминание, замена журнала через чат |
| `deploy/` | `compose.yaml`, `update.sh`, `backup.sh`, `import.sh`, `users.sh`, `.env.example`; `deploy/backup/` — образ контейнера копий |
| `tests/` | тесты: логика, сценарии бота на настоящем PostgreSQL, подделки мессенджера |
